# 圆桌秘书

项目最新定位（2026-09-29）：面向大学师生的教育秘书，功能围绕大学教学、学习和师生协作设计。此前面向办公、生活等多领域的通用秘书定位已调整，后续规划以[项目方向与范围](docs/项目方向与范围.md)为准。

第一阶段可运行骨架：原生微信小程序＋TypeScript＋NestJS 演示后台。

当前完成的是个人秘书入口、个人安排增删查改、演示后台身份隔离，以及可选的 PostgreSQL 持久化。**尚未接入真实微信登录、大模型、多 Agent 协商或消息推送。** 个人记忆已有数据模型，尚无完整业务功能。

当前联调分支已将小程序切换为 `api` 模式，需要启动本机后台。按 [双人联调启动指南](docs/双人联调启动指南.md) 操作；仅体验离线页面时可以把配置改回 `local`。

## 第一步现在如何运行

在项目根目录打开终端：

```powershell
npm.cmd install
npm.cmd run check
```

依赖已安装且文件未变化时，直接执行 `npm.cmd run build:mini` 即可。然后打开微信开发者工具：

1. 导入本项目根目录 `D:\万象无限\roundtable-secretary`。
2. `project.config.json` 已将小程序目录指向 `dist/miniprogram/`。
3. 当前配置已填写项目 AppID，使用已获该小程序开发权限的微信账号登录工具。若使用测试号，应在工具中选择测试号；不要手工将 `touristappid` 当作正式 AppID。测试号不能代替正式账号能力的验收。
4. 在“秘书”页点击“记一条个人安排”，填写虚构名称、日期和时间，确认保存。
5. 切换“日程”页查看或删除；重新编译／重新打开后，本机模式的数据仍在，清理缓存则会消失。

源码在 `apps/miniprogram/src`，每次修改后重新执行 `npm.cmd run build:mini` 再在开发者工具编译。不要编辑生成目录 `dist/miniprogram`。

## 两种演示模式

`local` 模式不联网、不要求启动后台。演示数据保存在当前微信开发工具或设备的本地存储中，**未加密，仅使用虚构数据**。

可选 `api` 模式用于开发者工具模拟器与本机后端联调：

```powershell
npm.cmd run build:api
npm.cmd run start:api
```

将 `apps/miniprogram/src/services/config.ts` 的 `mode` 改为 `api` 后重新构建小程序。后端地址默认为 `http://127.0.0.1:3000`。仅在本机调试时按开发者工具要求开启本地网络调试／跳过域名校验；生产配置不能关闭域名与证书检查。手机上的 127.0.0.1 是手机自身，不会连接电脑，该模式目前不用于真机后端联调。

后台只监听本机，使用随机演示凭证。`STORAGE_MODE=memory` 时重启清空会话和安排；`STORAGE_MODE=postgres` 时会话及安排存入数据库。两种模式的会话均会过期，过期后创建的是新演示身份，不能自动找回旧身份数据。不得把 `/dev/sessions` 当作微信登录或部署到公网。

## 已有安全边界

- 没有 API Key 输入框或保存接口，不收集真实模型凭证。
- 演示接口按随机会话身份访问本人安排，不接受客户端指定 owner。
- 错误中不返回其他人的记录，禁止缓存个人接口响应。
- 后台拒绝以 production 模式启动；入口拒绝监听公网地址。
- 本机演示没有真实多用户身份隔离，应视作同一设备上的一个测试用户。

这些只是开发阶段边界，不代表生产安全已经完成。正式接收用户数据之前仍需真实身份、数据库部署与权限配置、密钥管理、网关、限流、日志控制与完整安全测试。
