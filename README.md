# 圆桌秘书

原生微信小程序＋TypeScript＋NestJS＋PostgreSQL，当前支持个人日程、偏好记忆、一句话草稿、圆桌房间与共同时间协商。

当前已实现日程新增、查看、编辑、删除、北京时间规则、偏好与个人记忆管理、可选 PostgreSQL 持久化和微信登录接入代码。**真实微信换码和真机验收仍待配置；真实大模型网关、多 Agent 协商和消息推送尚未接入。** 页面上的秘书默认不接模型（`SECRETARY_MODE=off`），可切到 `stub` 用本地规则做演示，绝不伪造“AI 已理解”的假象。

## 第一步现在如何运行

在项目根目录打开终端：

```powershell
npm.cmd install
npm.cmd run check
```

依赖已安装且文件未变化时，直接执行 `npm.cmd run build:mini` 即可。然后打开微信开发者工具：

1. 导入本项目根目录 `D:\万象无限\roundtable-secretary`。
2. `project.config.json` 已将小程序目录指向 `dist/miniprogram/`。
3. 仓库配置了项目 AppID，使用该 AppID 需要开发者权限。没有权限时可在独立副本使用 `touristappid` 验证本机演示页面；游客模式不能验证真实登录或正式发布。
4. 在“秘书”页点击“记一条个人安排”，填写虚构名称、日期和时间，确认保存。
5. 切换“日程”页查看、搜索、按日期或状态筛选、编辑或删除；重新编译／重新打开后，本机模式的数据仍在，清理缓存则会消失。秘书页新增安排前会检查时间重叠，有冲突时可改时间或明确选择仍然保存。详见 [日程查找与冲突提醒](docs/日程查找与冲突提醒.md)。
6. 在“我的 → 管理我的记忆”新增偏好、限制或备忘，查看来源与更新时间，支持编辑、删除。偏好与限制会在生成草稿时提醒冲突，但不会替你改决定。详见 [个人记忆管理](docs/个人记忆管理.md)。
7. 在“秘书”页用一句话描述安排，点“让秘书整理成草稿”。**只会生成待确认草稿，确认保存后才写入日程。** 本机演示模式支持规则解析与分步补充，不联网、不调用模型；后台模式生成草稿需要 `SECRETARY_MODE` 不是 `off`。详见 [本机秘书对话与草稿](docs/本机秘书对话与草稿.md) 和 [个人秘书与模型接入](docs/个人秘书与模型接入.md)。
8. 在“圆桌”页发起活动。本机模式可预览单人流程；后台模式支持邀请码加入、成员管理与本次忙闲授权，最多 3 人，并可生成共同可用时间、发起方案、全员确认后写入各自日程。详见 [圆桌房间与授权](docs/圆桌房间与授权.md) 与 [协商与确认](docs/协商与确认.md)。
9. 会议未举办时，进入圆桌的“记录原因／查看复盘”，填写事实、责任比例与补救；外部原因和待查可单独保留。本机保存草稿，后台支持逐人确认、异议与修订历史。详见 [会议复盘与责任分配](docs/会议复盘与责任分配.md)。PostgreSQL 后台需先备份并应用新增复盘表迁移；本轮未修改主项目数据库。

10. 本机模式下，进入圆桌「会议工作台」管理补救任务、会前清单和带修订历史的会议纪要；复盘补救与纪要行动可预览后转为任务。日程页新增「周视图与统计」，查看七天安排、去重占用和本周任务。详见 [会议工作台与周视图](docs/会议工作台与周视图.md)。负责人及验收目前为本机手动记录，不跨设备分派或通知。

源码在 `apps/miniprogram/src`，每次修改后重新执行 `npm.cmd run build:mini` 再在开发者工具编译。不要编辑生成目录 `dist/miniprogram`。

后台模式下，停留在圆桌详情时会自动更新伙伴与方案状态，也可下拉刷新。断网会保留上次内容并暂停写操作，写入超时只查询结果、不自动重发。详见 [圆桌状态同步与弱网验收](docs/圆桌状态同步与弱网验收.md)。

## 两种演示模式

默认 `local` 模式不联网、不要求启动后台。演示数据保存在当前微信开发工具或设备的本地存储中，**未加密，仅使用虚构数据**。

可选 `api` 模式用于开发者工具模拟器与本机后端联调：

```powershell
npm.cmd run build:api
npm.cmd run start:api
```

将 `apps/miniprogram/src/services/config.ts` 的 `mode` 改为 `api` 后重新构建小程序。后端地址默认为 `http://127.0.0.1:3000`。仅在本机调试时按开发者工具要求开启本地网络调试／跳过域名校验；生产配置不能关闭域名与证书检查。手机上的 127.0.0.1 是手机自身，不会连接电脑，该模式目前不用于真机后端联调。

后台只监听本机。默认 `STORAGE_MODE=memory`、`AUTH_MODE=demo`，重启会清空内存会话与安排。`/dev/sessions` 仅用于演示，不是微信登录。

复制 `.env.example` 为不提交 Git 的本机 `.env`，配置 `DATABASE_URL` 和 `STORAGE_MODE=postgres`，执行 `npm run db:deploy` 后可使用持久化存储。演示会话有效期一小时，有效期内重启可恢复；过期后创建的新演示身份不能自动找回旧身份。

启用 `AUTH_MODE=wechat` 后，后台必须配合 PostgreSQL、`WECHAT_APP_ID` 和后台专用 `WECHAT_APP_SECRET`；小程序设置 `mode: 'api'`、`authMode: 'wechat'`。同一微信用户重新登录可找回本人日程，详见 [微信登录接入](docs/微信登录接入.md)。

数据库验证执行 `npm run test:postgres`：在本机数据库创建随机独立 schema，测试后清理，不重置 public。常规 `npm run check` 不要求数据库，默认跳过数据库集成测试。

后台启动后可运行 `npm run check:api -- http://127.0.0.1:3000 --require-postgres` 做只读检查。`/health` 表示进程存活，新增 `/ready` 检查业务表与列，数据库故障或迁移缺失返回 503；启动也会拒绝缺表环境。命令不会创建账号、修改日程或调用模型，详见 [后台就绪与部署前检查](docs/后台就绪与部署前检查.md)。这些检查不等同于已经具备正式公网部署条件。

保存日程现在附带请求编号：同一运行内保存失败后原样重试不会重复创建，数据库模式跨后台重启仍有效。升级时需应用新增迁移；规则与客户端边界见 [日程保存与重试](docs/日程保存与重试.md)。

## 已有安全边界

- 没有 API Key 输入框或保存接口，不收集真实模型凭证。
- 个人接口按后台会话访问本人安排，不接受客户端指定 owner。
- 微信模式关闭演示登录；自建会话只保存令牌摘要，不返回微信 OpenID、session_key 或 AppSecret。
- 错误中不返回其他人的记录，禁止缓存个人接口响应。
- production 模式须通过 PostgreSQL、微信身份、凭证与 HTTPS 地址校验；入口仅监听本机，由 Nginx 提供 HTTPS。
- 本机演示没有真实多用户身份隔离，应视作同一设备上的一个测试用户。

这些边界不代表生产安全已经完成。正式接收用户数据前仍需真实账号验收、部署与 HTTPS、模型密钥管理、限流、监控和完整安全测试。

## 下一阶段

当前优先完善小程序功能，服务器与部署暂缓。local 模式已支持本机规则秘书的分步追问与草稿确认，不需要服务器或密钥，见 [本机秘书对话与草稿](docs/本机秘书对话与草稿.md)。

正式小程序可通过 `npm run build:mini:release -- --api-origin https://实际后台域名` 独立构建，强制微信身份和 HTTPS，不修改本机演示配置。产物检查与导入步骤见 [正式小程序构建](docs/正式小程序构建.md)。

已提供生产启动校验、登录限流、Nginx/systemd 模板及恢复步骤，见 [正式部署与真实登录](docs/正式部署与真实登录.md)。目前尚无服务器和域名，未进行公网部署或真实登录验收。部署后运行 `npm run check:api -- https://实际后台域名 --require-production`。

秘书页现可读取生成模式与可用状态，后台增加模型域名、模型名称白名单和单进程调用限流。HTTP 模式需填写 `SECRETARY_ALLOWED_MODELS`；配置与边界见 [个人秘书与模型接入](docs/个人秘书与模型接入.md)。

运行 `npm run check:setup` 检查微信登录配置缺项，补齐后台凭证、HTTPS 和合法域名后，验收两个真实账号的完整流程。继续完善模型连接管理与部署。见 [项目任务清单](docs/项目任务清单.md) 和 [本地演示验收](docs/本地演示验收.md)。
