## A：启动小程序

1. 打开微信开发者工具，导入项目根目录。
2. 使用有开发权限的微信账号及对应 AppID；测试号能用的范围以工具提示为准。
3. 本机 HTTP 联调时，在工具的本地设置中按需启用“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。此设置仅用于本机开发。
4. 后台启动后点击“编译”。修改小程序源码后先执行 `npm.cmd run build:mini` 再编译。
5. 进入日程页应能读取后台；页面报无法连接时先检查后台是否运行。

## B：启动后台

### 本机 PostgreSQL 的安装方式

使用 PostgreSQL 官方下载页链接的 EDB 17.11 Windows 二进制包，按当前用户安装到 `%LOCALAPPDATA%\RoundtableSecretary\postgres17`。数据库数据在该目录的 `data` 子目录，不进入 Git 仓库。管理员凭证仅保存在这个受当前用户与 SYSTEM 权限保护的目录；应用使用独立的非超级用户 `rt_app`。

没有注册开机服务，电脑重启后先运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/local-postgres.ps1 start
```

查看状态或停止数据库：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/local-postgres.ps1 status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/local-postgres.ps1 stop
```

`setup-local-postgres.mjs` 只用于首次配置，并拒绝覆盖已有数据库和 `.env`。队友可以使用自己的 PostgreSQL 安装方式，只需按照下文设置连接串并执行迁移。

### 内存模式：先验证网络与页面

代码默认使用内存模式。如果已经配置了 PostgreSQL `.env`，需要将其中 `STORAGE_MODE` 改为 `memory` 后才能切换到内存模式。启动：

```powershell
npm.cmd run start:api
```

保持该终端运行。在另一个终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3000/health
```

`persistence` 应为 `memory`。此模式重启会丢失演示数据。

### PostgreSQL 模式：验证数据持久化

前提：本机 PostgreSQL 已运行，已建立专用开发库和可执行迁移的开发账号。不要使用生产数据库做本轮联调。

在项目根目录创建不提交 Git 的 `.env`，按实际情况填写：

```dotenv
HOST=127.0.0.1
PORT=3000
STORAGE_MODE=postgres
DATABASE_URL=postgresql://USER:URL_ENCODED_PASSWORD@127.0.0.1:5432/roundtable_dev?schema=public
```

连接串中的密码特殊字符需要 URL 编码。密码只保存在本机，不发到聊天、截图或仓库。启动程序从项目根目录加载 `.env`；已有环境变量可能覆盖文件值。

```powershell
npm.cmd run db:generate
npm.cmd run db:deploy
npm.cmd run db:status
npm.cmd run test:postgres
npm.cmd run start:api
```

如内存后台正在运行，先在其终端按 Ctrl+C 停止，再启动 PostgreSQL 模式。检查 `/health` 的 `persistence` 必须为 `postgres`。

真实数据库测试会创建随机隔离 schema，结束后清理该 schema，不重置 public；测试账号需要创建 schema 和执行迁移的权限。

## 两台电脑与真机

每人连接自己的 localhost 后台时，双方数据相互独立。手机的 127.0.0.1 指向手机本身，不能连接电脑后台。当前后台限制监听本机；共享测试后台与真机网络访问需要单独配置，不在本轮直接开放。
