# 协作任务与站内消息

更新：2026-10-13。用户确认暂无线上的 HTTPS 环境，本轮完成后台代码、本机 HTTP 双演示账号页面联调和 PostgreSQL 持久化验证。

## 当前可用范围

后台模式中，从圆桌详情或复盘页进入「协作任务」。发起人可分派给当前成员、设置截止日期与任务说明；负责人本人开始执行并提交完成说明。提交时的全部成员各自登录后填写验收意见，全员接受才显示完成。

「我的 → 站内消息」显示任务分派、提交、验收、异议、重开等事件，支持本人已读状态。消息和任务在同一事务中保存，不会发生任务失败但产生成功消息的情况。

本机工作台继续独立保存任务、会前清单和纪要。本机记录不会自动上传。后台已提供共享会前清单与纪要；后台协作任务尚未纳入日程周统计。

## 权限与共同验收

- 发起人创建、修改、重新分派任务。修改待开始或进行中的任务后恢复待开始；待验收、异议或完成的任务须先重开。
- 只有当前负责人本人能开始执行、提交完成说明；发起人不能替负责人提交。
- 至少两名当前成员才能提交共同验收。提交时冻结本轮名单，新增成员不自动加入已经发起的验收。
- 每人只能记录自己的确认或异议；验收与异议说明必填。存在异议时不能显示完成，同一成员改变态度也保留旧操作记录。
- 发起人或负责人可写明原因重开。下次提交采用新的当前成员名单，全部重新确认。
- 成员退出或被移除后不能再读取工作台与消息。若正在验收的名单包含离开成员，不能悄悄缩减人数来完成；须重开、必要时重新分派，再提交。
- 已经完成的历史不因之后成员退出而删除。后台消息查询按当前成员关系过滤，前端缓存不会赋予服务器访问权限。

所有写入校验工作台版本。两人拿着同一旧版本同时表态，只有一人成功；另一人刷新后再表态，避免覆盖。请求失败不自动重发；页面保留输入并先要求刷新核对结果。

页面停留时约每 15 秒刷新伙伴进展；编辑期间暂停自动刷新，离页取消计时器，旧响应不会覆盖新页面。

## 站内消息的边界

当前实现的是应用内消息中心，不是微信订阅推送，也没有到期定时提醒。本人操作不会给自己产生事件通知；其他当前成员接收对应进展。每个圆桌保留最新 200 条事件，列表汇总当前仍可访问圆桌中最新 100 条本人消息；未读数只计算当前列表。消息保留上限不等于永久审计存档，任务操作历史另行保留。

微信订阅消息的模板、用户授权及发送通道尚未接入。本轮没有发送真实微信消息。

## 无需服务器的本机体验

在项目根目录，先启动独立演示后台：

```powershell
npm.cmd run demo:api
```

它只监听 `127.0.0.1:3302`，使用演示身份、内存存储和规则秘书，不读取项目 `.env`，不连接真实模型或数据库。关闭服务会清空这些演示记录。不要用于正式环境。

保持此终端运行，在另一个终端执行：

```powershell
npm.cmd run demo:mini
```

将输出的新目录导入微信开发者工具。它是独立游客副本，使用后台演示模式，不修改主项目配置、AppID 或域名校验设置。每次生成新目录，不复用或清理已有演示缓存。此地址只供电脑模拟器使用；手机上的 127.0.0.1 指向手机自身。

实际自动验收通过两套独立演示会话经本机 HTTP 验证双方身份与页面操作；它不等同于两个真实微信账号或两台真机。

## 后台接口

```text
GET  /roundtables/:id/work
POST /roundtables/:id/work/tasks
PUT  /roundtables/:id/work/tasks/:taskId
PUT  /roundtables/:id/work/tasks/:taskId/action
GET  /me/notifications
PUT  /roundtables/:id/work/notifications/:noticeId
```

任务保存：`version, title, details, dueDate, assigneeMemberId`。状态操作：`version, action, note`，action 为 start / submit / accept / dispute / reopen。已读接口接受空对象，身份从后台会话取得，不能提交他人的 userId。只读接口不修改任务状态。

每个圆桌最多 50 个协作任务、50 个准备事项，每任务或准备事项最多 50 条操作历史，纪要最多 20 版，完整文档最多 300,000 UTF-8 字节。达到上限拒绝本次写入，保留旧记录；任务目前不提供删除。

## 持久化迁移与恢复

沿用迁移 `20261007010000_shared_workspace`，对应 `shared_workspaces` 表。共享任务、验收意见、任务历史、消息接收人及已读状态在同一份文档中持久化。修改与成员校验在串行化事务中进行，圆桌行锁协调成员变更。后台启动和就绪检查要求新表及列存在。

本轮仅在随机独立测试 schema 执行迁移，未修改主项目数据库。正式启用 PostgreSQL 后台前，先按已有部署文档备份数据库，再运行 `npm.cmd run db:deploy` 和后台构建。代码回退时可以保留新增表，不通过删表或清库回退。

## 共享会前清单与会议纪要（2026-10-13）

在后台工作台选择「会前清单」「会议纪要」「协作任务」。发起人给当前成员分派准备事项；只有负责人本人可填写说明并确认就绪或撤回。任何编辑都会重置就绪状态，旧说明保留。负责人退出后显示待重新分派；重新加入也不继承旧成员身份。

纪要由发起人记录，日期须在圆桌日期范围内；摘要必填，决议与后续行动选填。每次保存产生新版本，不覆盖历史。决议是发起人记录，不代表全员同意。后续行动每行一项，最多 10 项，每项 500 字且合计 1000 字。

仅最新版行动可预览并分派：确认真实负责人及截止日期后才新建待开始任务，取消预览不写入。同版同项不能重复转入；后续修订不会覆盖已创建任务。不同修订可能描述相同工作，分派前应核对已有任务。任务仍须负责人本人提交和逐人验收。

准备、纪要和转入任务的事件与业务写入同事务保存；消息打开对应工作台标签。共享内容沿用原工作台 JSON 文档，本轮无需新数据库迁移，旧文档缺新字段时按空清单和空纪要处理。本机备份只包含本机记录，不含后台共享内容。

新增接口：

```text
POST /roundtables/:id/work/preparation
PUT  /roundtables/:id/work/preparation/:itemId
PUT  /roundtables/:id/work/preparation/:itemId/action
POST /roundtables/:id/work/minutes
POST /roundtables/:id/work/minutes/:revision/actions/:index
```

准备保存字段同任务保存；状态操作为 version, done, note。纪要保存为 version, date, summary, decisions, nextSteps（按行文本）；转入动作为 version, assigneeMemberId, dueDate。服务端拒绝额外字段、越权和过期工作台版本；失败后刷新核对，不自动重试。
