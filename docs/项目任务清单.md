## 建议分工

本轮新增：日程查找和保存前冲突提醒已完成。支持组合搜索、状态筛选、日期分组；重叠先展示、再次确认才保存，读取失败与旧检查不触发写入。常规检查为 138 项通过、1 项数据库套件默认跳过；独立游客项目两组共 12 项页面流程通过。见 [日程查找与冲突提醒](日程查找与冲突提醒.md)。此前本机规则秘书的 6 轮对话与草稿确认继续保留。

A 负责小程序页面、真实账号操作、真机体验和演示材料；B 负责后台、数据库、会话、安全和协商逻辑。接口字段、状态、日期时区以及每轮验收由两人共同确认。

下一阶段先完善个人秘书、日程和圆桌的使用体验，继续基于本机演示与独立测试数据验证。购买服务器、配置域名和正式部署按用户要求暂缓，不作为继续开发功能的前置条件。真实微信登录和多人跨设备使用仍需之后单独验收。

本轮 `npm run check` 为 138 项通过、1 项数据库套件默认跳过，类型检查与小程序构建通过；此前数据库单独检查为 46 项通过，本轮未改后台与迁移，未重跑数据库集成套件。开发者工具独立游客项目完成日程搜索筛选及冲突提醒两组页面验收，无真实登录和模型调用。已有正式构建与部署说明继续保留供之后使用。

## 完成与恢复规则

1. 每批改动先运行类型检查和相关自动化测试，再做真实接口联调。
2. “代码完成”“自动化通过”“真实账号通过”分别记录，未测试项目不勾选完成。
3. 使用功能分支和 PR，合并前保留可定位的 Git 提交或标签，不强制覆盖共享历史。
4. 代码回退使用 Git 历史；数据库迁移前保留备份，不通过清空数据库来恢复代码。
5. 备份在独立本机数据库验证后再用于恢复；`.env`、令牌、AppSecret 和数据库备份均不提交 Git。

运行步骤见 [微信登录接入](微信登录接入.md)。本轮自动化证据与限制见 [本地演示验收](本地演示验收.md)。
