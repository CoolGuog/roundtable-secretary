# DeepSeek 接入与 Demo 验收

本次完成真实模型的日程草稿接入层。个人 API 配置页面、工具调用循环与双秘书协商属于下一阶段；当前两个测试用户共用后台配置的模型账户，但按各自会话读取本人的偏好。

## 本机配置

在 DeepSeek 开放平台创建 API Key，并确认账户可调用 API。不要把 Key 发到聊天、截图或提交到 Git。

在 PowerShell 执行：

```powershell
cd D:\万象无限\roundtable-secretary
npm.cmd run model:setup
```

输入隐藏的 Key 后，脚本会完成：

1. 验证输入格式，把模型相关配置写入被 Git 忽略的 `.env`，保留数据库、微信等其他配置。
2. Windows 下将新配置文件的读取权限限制为当前用户和 SYSTEM。密钥存储在本机文件中，不代表经过加密存储。
3. 使用一条虚构的“明天下午三点到四点讨论课程项目”调用真实模型，验证返回的日期和时间。会消耗少量模型 API 用量，不读取数据库里的日程或记忆，不新增日程。
4. 测试成功后重启本仓库的后台，检查模型模式及存储就绪状态。端口被其他程序占用时停止，不会强行结束其他程序。

如果本机还没有 API Key，代码可以构建和测试，但不能验证真实调用；此时保留原来的 off 模式和手动录入能力。

默认模型为当前官方文档示例中的 `deepseek-flash`。如账户使用另一个模型名称，可以执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/configure-deepseek.ps1 -Model 你的模型名称
```

单独重新验证连接：

```powershell
npm.cmd run model:check
```

该命令每次发起一次实际模型调用。失败时提示密钥、余额、限流、配置、超时或格式问题，不输出上游原始错误正文。连接测试失败后的配置仍保存在 `.env`；修正后重新运行 setup，或检查通过后手动重启后台。

## 接入方式

- 官方 HTTPS 地址：`https://api.deepseek.com/chat/completions`。
- 显式关闭思考模式，使用 JSON Output，单条输出最多 800 tokens，批量最多 5000 tokens。
- 单条后台请求最长 25 秒，小程序请求最长 35 秒；批量分别为 55 秒、65 秒；普通日程接口仍为 10 秒。
- 上游响应体最多 256 KiB，空结果、截断、非法 JSON 或字段类型不符均提示失败。
- 日期、时间和名称经过后台校验，模型返回不直接写数据库。
- 每次只提供用户本次描述、北京时间日期、最多 20 条本人偏好，不发送课程表、其他用户偏好、数据库用户 ID、模型 Key 或数据库凭证。
- 当前偏好选择沿用已有列表的前 20 条，并非语义检索。复杂偏好和 Agent 工具读取将在下一阶段实现。
- 每个用户最多每分钟 6 次整理、同时 1 次，全后台最多并发 4 次。失败请求也占本机限流额度，不会自动重试写入或反复调用模型。
- 状态中的 `connectionVerified` 表示本后台进程曾成功收到可解析结果，`lastSuccessfulAt` 是最后成功时间；不保证下一次请求一定成功。独立 CLI 测试不改变运行中后台的状态记录。

## 小程序验收和录屏片段

使用 `dist/demo-A` 和 `dist/demo-B`，点击“编译”。`dist/demo-local` 为离线演示，不调用外部模型。

1. 打开秘书页，确认提示模型已配置；“让秘书整理成草稿”按钮可用。
2. A 用户添加一条虚构偏好，例如“尽量安排在下午”；B 添加不同偏好。
3. 输入“明天下午三点到四点和同学讨论课程项目”，点击整理。
4. 页面显示本次模型名称、待确认日期和时间；日程页此时没有新增记录。
5. 可逐条修改、取消勾选，点击“确认写入勾选的安排”，再次确认后日程页出现安排；若时间重叠，需明确确认冲突。
6. 输入缺少时间的需求，检查草稿提示补全，不伪造已保存结果。当前后台支持单轮整理，信息不足时可以手动补全，尚未开放后台多轮追问。
7. 网络或账户异常应给出顶部浮窗和可见的失败结果，填写内容保留，允许重试或手动填写。

录屏时只展示小程序界面，不展示 `.env`、API Key 配置终端或平台密钥页。当前阶段可以录制“真实模型整理个人安排”，双 Agent 协商需下一阶段完成后再录制。

## 批量日程（2026-10-11）

大模型模式使用鉴权接口 `POST /me/secretary/drafts`，只接受 `text`（最多3000字），返回最多20类草稿。原单条接口保留兼容；本机规则演示仍为单条。

示例：工作日8:30—11:00上课，12:00—14:00午休，下午在图书馆学习，18:00—19:00晚饭，游戏不用记入。模型应提取4类每周一至周五的安排，不展开为每天的独立记录。学习起止时间、没有说明的重复起止日期留空，用户逐条补充。模型提取可能有误，必须核对。

“修改 / 补充”只更新草稿；只有最终批量确认才调用已有日程保存接口。保存前校验全部勾选草稿，并检查每条开始日起最多31天与已有日程及本批草稿的重叠。更远日期未在此预检查，圆桌仍按实际活动日期检查。

批量按条保存，并非数据库全批事务。中途失败后保留已保存标记，重试只写未成功事项。网络结果不确定的那条暂停修改，允许原样重试，复用现有幂等键；这些键只在本次小程序运行中保留。重新编译前应先核对日程，避免丢失重试状态。草稿不持久化，重新编译会丢失未保存内容。

验证：真实 DeepSeek 对上述合成示例返回4类草稿并排除游戏；自动测试覆盖缺项、重复规则、鉴权、输入上限、确认前不写入、内部冲突、部分失败与重试。
