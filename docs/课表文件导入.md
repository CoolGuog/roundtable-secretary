# 课表文件导入

秘书页提供“上传截图”和“选择聊天文件”。支持 PNG/JPG、PDF、XLSX、UTF-8 CSV；旧版 XLS 请另存 XLSX。每个文件最多4MB，PDF最多3页，表格最多5个工作表、300行、40列；文字最多12000字。当前需连接后台和已配置的模型，离线预览不提供此入口。

## 使用流程

1. 上传前裁剪学号等无关信息，确认文件发送到本机后台。
2. 图片在本机预览，默认直接看图，不经过本机OCR。PDF和表格仍先解析为可核对文字；表格保留单元格地址，PDF文字保留坐标。
3. 可补充学校节次时间、课程周次及学期范围。图片已有时间轴时直接读取；学期开始日优先根据课表推算，没有依据时秋季默认9月1日（1月归上一年秋季）、春季默认3月1日，结束日默认往后4个月。日期只是可修改的预填值，不代表真实校历。
4. 点击“让模型直接看图整理”或“整理课程草稿”，确认将原图或核对后的文字与补充信息发送给已配置模型（消耗模型用量，不发送个人记忆）。
5. 核对生成的课程、星期、日期、时间和重复截止日期，修改或取消勾选，最终确认才写入日程。

模型最多输出20类草稿。OCR可能错字、串列，模型换算也可能有误。单双周、隔周、离散周、节假日停课及调课尚未实现专门的数据结构，本版提示模型排除并说明，用户必须核对未导入说明，必要时按实际日期手动记录，不能当作完整学期导入保障。

## 文件处理与隐私

- 上传接口需要登录，沿用每人每分钟6次的秘书限流，全后台同时只解析1份文件。
- 校验后缀与文件签名；限制原文件、ZIP解压大小、工作表规模、PDF页数与渲染像素；禁止含公式的表格（先转为值）。
- 解析在独立线程执行，设置JS堆上限与90秒超时；这不是完整的操作系统沙箱。公网部署前应把不可信文档解析迁到独立容器并设系统级内存/CPU限制。
- 原文件只在后台内存处理，不创建文件数据库记录；图片直传模型经鉴权接口`POST /me/secretary/course-image`，使用base64图片内容，不创建公开图片URL。原OCR接口作为文件解析路径保留；扫描PDF的OCR使用本地语言包。
- 图片由用户确认后发送原图到DeepSeek；其他文件核对后发送提取文字。模型服务商的数据处理政策仍适用。文件与草稿不持久化到后台，已确认日程按原有数据库逻辑保存。
- 小程序正式部署需要HTTPS，并配置request和uploadFile合法域名；本机A/B调试沿用当前配置。

## 实现与验证

采用 [Tesseract.js](https://github.com/naptha/tesseract.js) 本机OCR、[PDF.js](https://mozilla.github.io/pdf.js/) 提取及渲染PDF、[ExcelJS](https://github.com/exceljs/exceljs) 读取表格。没有增加额外识图API配置。

图片默认使用现有DeepSeek Flash原生多模态接口，依据[官方Vision文档](https://api-docs.deepseek.com/guides/vision/)。模型返回中文星期名，程序转换为数字，避免模型混用“周一=0”和“周日=0”的编号规则；跨节色块按整体识别。直接看图仍可能误判底边和被截断的文字，不能保证100%准确，用户需对照原图修改确认。后台看图超时90秒，小程序上传请求110秒。

自动测试涵盖中文截图、文字PDF、扫描PDF、XLSX、CSV、伪文件、体积超限、公式拒绝、接口鉴权以及确认前不写入；小程序测试覆盖上传取消、识别文字核对、模型调用阶段分离和迟到结果丢弃。真实微信文件选择和复杂学校课表布局仍需用户在开发者工具验收。

依赖审计：新增表格库的uuid依赖覆盖至11.1.1以修复告警，验证使用到的v4接口及表格读写。原有Prisma 6.19.3工具链的deepmerge-ts告警仍需单独安排兼容升级；未执行会降级Prisma的audit --force。
