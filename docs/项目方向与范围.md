# 圆桌秘书：项目方向与范围

更新日期：2026-09-29。

## 已确认的方向变更

用户明确要求：项目从覆盖办公、学习、教育等多个领域的通用秘书，转向教育类秘书，主要功能贴合大学师生使用。

- 项目名称继续使用“圆桌秘书”。
- 主要用户为大学生和大学教师。
- 核心场景集中于大学教学、学习和师生协作。
- 后续需求、页面、示例数据、功能优先级及参赛介绍均按此定位制定。
- 原方案中面向通用办公和家庭生活的扩展不再作为当前开发主线。

本文件记录最新产品决策。旧方案和双人分工文档中与本定位冲突的场景描述，以本文件为准；已有技术实现和测试结果不因定位调整而自动改变。

## 延续的产品基础

当前仍以微信小程序为产品入口，延续个人秘书、个人记忆、日程和多人圆桌协商的基础思路。用户自带模型 API 的既有路线和信息安全要求继续保留，具体交互与功能结合教育场景细化。

已有日程、数据库和身份隔离工作可作为教育秘书的基础。未来共享信息时，需按场景和授权判断；教师身份本身不意味着可以读取学生的私人日程、记忆或模型密钥。

## 后续细化的候选场景

以下为符合新定位的候选方向，尚未确定为全部必做功能，也未确定开发顺序。

| 用户 | 候选场景 | 秘书可能提供的帮助 |
|---|---|---|
| 学生 | 课程、作业、考试安排 | 整理截止时间，协调学习计划与个人时间 |
| 学生小组 | 课程项目、实验、答辩准备 | 协商讨论时间，跟踪分工与任务进度 |
| 教师 | 课程教学与答疑 | 整理教学任务，安排答疑时间和预约 |
| 师生共同 | 导师会面、课题讨论、阶段汇报 | 各自秘书根据授权交换必要约束，提出共同可行安排 |

## 下一步产品工作

先选择一个大学师生使用的核心场景，明确参与角色、发起方式、秘书职责、共享信息范围和完成标准，再更新详细功能方案及双人分工。不要把候选场景直接当作已经确定的开发清单。
