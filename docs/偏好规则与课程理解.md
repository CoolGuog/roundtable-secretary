# 偏好规则与课程理解（2026-10-16）

默认不增加任何额外限制。支持两种方式，可组合使用。

## 自然语言习惯

在“我的 → 偏好与记忆”直接填写，例如“娱乐活动安排在当天最后一节课结束之后，会议可以安排在两节课之间”。开始协商前，每位用户自行开启“允许我的秘书读取日程名称和时间”，再确认授权；发起人选择娱乐或其他活动。

授权后增加 `read_schedule` 工具，向本人的模型上下文发送圆桌日期范围内的日程名称、日期和起止时间，不发送内部ID。最多300条，超过时要求缩小范围，不截断后假装完整。模型根据名称辨认课程，选择更符合偏好的候选，并给出简短建议理由。名称模糊、未写缓冲分钟等情况仍需主人核对；没有新增自动分类字段，也不保证自由文字被完全遵守。

没有开启日程名称授权时，模型只能知道候选可不可用，不能据此确认“最后一节课”。授权默认关闭。授权变化会停止正在进行的协商。个人日程、规则原文和模型建议理由不传给伙伴；模型提供方会收到本人明确授权的数据。

## 可校验规则模板

在记忆页选择“添加可校验安排规则”，选择“娱乐活动”或“所有活动”，再选择仅周末、仅周六、当天无其他安排，或前后各留30/60/120分钟。确认保存后生效，删除该条记忆则移除。娱乐规则仅在发起人将本次标为娱乐时适用。

模板保存为普通CONSTRAINT记忆，标题固定为“可校验安排规则”，内容使用明确格式。例如“娱乐活动：前后各留出60分钟”。后端精确解析，不模糊匹配自然语言。编辑模板时应保留格式，否则按普通文字处理；程序支持0—240整数分钟。多条规则同时成立，重复缓冲相当于取更严格的限制。

这些规则仅过滤秘书协商候选，并在生成方案前再次检查；不阻止个人手动安排，不自动改动已生成的方案。生成之后改规则，应撤回旧方案重新协商。主人最终接受仍沿用现有日程冲突检查，未把规则更新纳入数据库确认事务。

“当天无其他安排”针对所有日程，不冒充“当天没有课程”；缓冲同样针对所有安排，读取圆桌日期范围前后各一天来检查跨午夜相邻日程。只有候选布尔结果发给未授权名称的模型，不发送边界日期的日程原文。

## 推荐说明

成功后协商页显示“本人的方案核对”：程序检查结果与“模型建议理由（需核对）”分开展示。每人只能看到自己的理由。程序能证明候选无日程重叠及满足已识别模板；不能证明模型完全理解了全部自然语言偏好。

## 验收

1. B建立同一天09:00—10:00高数课和14:00—16:00英语课。
2. B填写“娱乐只能在最后一节课后；课程会议优先在两节课之间”。A填写全天有空。
3. 双方授权忙闲、偏好及日程名称，A选择娱乐活动并开始。检查生成时间在16点后。
4. 另建课程会议圆桌，选择其他活动，检查是否提出10点至14点的课间时段。
5. B添加“所有活动：前后各留出60分钟”，再次生成方案，确认程序排除了紧邻课程的候选。
6. 检查A页面及公共消息不含B的课程名称或偏好原文；未授权名称的场景不允许调用该读取工具。
