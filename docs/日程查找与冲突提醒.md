# 日程查找与冲突提醒

更新日期：2026 年 10 月 5 日。

本轮继续完善无需服务器的本机小程序功能。后台模式使用同一套页面，通过现有个人日程接口读取当前账号记录；未新增接口或数据库迁移。

## 查找已有安排

进入「日程」，可按名称搜索，选择「全部／今天／未结束／已结束」，也可选具体日期。三个条件可以组合；点击「清除筛选」恢复全部记录。

列表按日期分组，显示今天、明天、星期，以及每条安排的「待开始／进行中／已结束」。所有时间按北京时间计算，页面每分钟更新状态，离页停止计时，不额外请求后台。「未结束」包含正在进行的安排，结束时间等于当前分钟时视为已结束。

分类数字统计完整列表，结果数字表示组合筛选后的条数。编辑后的名称不再匹配关键词时，记录会从当前结果中消失，但没有被删除；清除筛选或搜索新名称即可找到。搜索、筛选、排序本身不会写入记录。

## 保存前检查时间

在「秘书」手动填写或整理草稿后，点击「确认保存」：

1. 先验证名称、有效日期与同日开始／结束时间，再读取本人日程。
2. 没有重叠就保存；有重叠则列出名称、日期和起止时间，暂不保存。
3. 可以修改表单，或者点击「仍然保存这条安排」。再次确认会重新读取日程；草稿或冲突内容变化时，需要重新确认。
4. 读取失败明确提示「尚未保存」，保留草稿供重试，不把网络错误当成没有冲突。

例如已有 14:00—15:00 的会议：安排 15:00—16:00 不算冲突，安排 14:30—15:30 会提醒。仅比较同一天的时间，暂不支持跨午夜安排。

检查期间编辑、关闭表单、开始新草稿或离开页面，会撤销旧检查；迟到的结果不能自动保存。连续点击不会重复发起保存。已有的保存失败后原样重试去重逻辑继续保留；未收到写入响应时仍应先查看日程确认结果。

- 完整 `npm run check`：138 项通过、1 项数据库集成套件默认跳过；类型检查和小程序构建通过。

冲突检查是保存前提醒，不是多人并发锁。检查与写入之间若其他设备改动日程，仍可能产生新冲突。当前提醒入口是秘书页新增安排；日程页编辑仍使用原有编辑流程，不声称已覆盖编辑冲突检查。圆桌全员确认保留已有后台事务与冲突校验。

本轮没有改后台或数据库，未重跑 PostgreSQL 集成套件；没有配置服务器、部署公网、调用真实模型或验收真实微信登录。本机数据仍只保存在当前开发者工具／设备，不能跨设备同步，验收仅使用虚构安排。
