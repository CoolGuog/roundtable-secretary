# 第一阶段开发记录

日期：2026 年 9 月 20 日

## 目标

建立圆桌秘书可运行工程，验证“进入页面—录入个人安排—确认保存—读取／删除”的基本路径，为后续真实微信身份和秘书记忆打基础。

## 本次实现

- 原生小程序的秘书、圆桌、日程、我的四个页面；圆桌明确标记为待实现。
- TypeScript 构建流程、微信开发者工具项目配置、依赖锁文件。
- 默认无需联网的本机演示数据服务。
- 可选的 NestJS 演示后台，随机会话令牌、本人范围读取和修改、输入校验。
- 后台 HTTP 集成测试，覆盖匿名请求、跨用户删除、恶意所属字段、日期时间与并发隔离。

本次使用 Codex 辅助梳理首个开发切片、编写工程与测试、检查执行结果。AI 工具的关键交互与代码变更应在参赛开发过程中持续归档，不以本文件替代完整过程材料。

## 设计取舍

首个切片采用原生基础组件完成页面，TDesign 暂未引入，避免在验证最小业务时增加不必要依赖。后续统一 UI 时按总方案接入。

没有提前加入数据库、Redis、真实模型密钥或复杂协商代码。演示模式与未来生产模式需要明确分开；现有内存数据只用于测试，后端不对公网提供服务。

## 下一阶段任务

1. 落实小程序 AppID 和开发者权限；AppSecret 只配置在本地安全环境或后台密钥服务，不发到聊天。
2. 接入 wx.login 与后端微信凭证校验，移除生产路径中的演示登录。
3. 创建 PostgreSQL 数据模型、迁移和本人范围的访问服务。
4. 验证两个真实测试账号不能互相读取或修改记忆和安排。
5. 再建设独立模型网关、密钥加密和调用预算，之后开放模型连接界面。

- `npm.cmd run check` 通过：前后端 TypeScript 类型检查、5 项后台 HTTP 集成测试、小程序构建。
