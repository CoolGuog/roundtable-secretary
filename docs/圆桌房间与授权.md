# 圆桌房间与本次授权

更新日期：2026 年 9 月 29 日。

## 已实现的操作

在“圆桌”页发起活动，填写名称、目标、日期范围、每天可选时间窗口和活动时长。创建后进入详情，发起人可复制邀请码，伙伴在圆桌页通过邀请码加入。

首版每桌最多 3 人，每人最多同时参与 20 个进行中的圆桌。日期范围最多 31 天，按北京时间解释；时长为 15 至 240 分钟、15 分钟的倍数，不能超过每日时间窗口。

发起人可以更新邀请码、移除其他成员和关闭圆桌；普通成员可退出。移除成员时会自动更新邀请码，旧码立即失效；退出则只删除自己的成员关系。发起人不能退出或移除自己，需要关闭圆桌。关闭后不能加入、更新邀请或修改授权，原成员仍可查看活动记录；重复关闭不会再次修改版本。

邀请码为随机 20 位十六进制字符，有效期 7 天；仅发起人可从接口取得邀请码。邀请码持有者可以申请加入，发起人应只分享给预期伙伴。重复加入不会重复创建成员。不同微信 AppID 的账号不能交叉加入；演示身份与微信身份也不混用。

## 授权边界

- 加入圆桌会让其他成员看到自己的昵称、角色以及本次授权状态。
- 忙闲授权默认关闭；每个人只能授予或撤回自己的授权。
- 授权范围限于本圆桌的日期和每日时间窗口，不包含日程标题、原因或个人记忆。
- 后台按本次授权读取起止时间计算共同空闲，不读取标题或个人记忆；全员接受后才写入各自日程，详见 [协商与确认](协商与确认.md)。
- 退出和被移除会删除本桌授权；关闭圆桌会撤回所有成员的忙闲授权。
- 非成员统一返回 404；成员执行发起人专属操作返回 403。接口不返回内部用户 ID、微信身份或私人记忆。

成员变化、授权变化、邀请更新和关闭会递增房间版本，为后续带版本协商与确认提供基础。当前活动需求创建后不支持修改；需要改变目标或窗口时新建圆桌，避免让旧授权覆盖新范围。

## 接口

以下接口均要求有效 Bearer 会话，身份由后台识别。

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/roundtables` | 本人参与的圆桌 |
| POST | `/roundtables` | 创建圆桌，自动成为发起人成员 |
| POST | `/roundtables/join` | 仅传 `{ code }` 加入 |
| GET | `/roundtables/:id` | 成员读取详情 |
| PUT | `/roundtables/:id/membership` | 仅传 `{ shareBusy: boolean }` 修改本人授权 |
| DELETE | `/roundtables/:id/membership` | 普通成员退出，成功返回 204 |
| POST | `/roundtables/:id/invitation` | 发起人轮换邀请码 |
| DELETE | `/roundtables/:id/members/:memberId` | 发起人移除成员并轮换邀请码 |
| POST | `/roundtables/:id/close` | 发起人关闭圆桌 |

创建字段：`title`（1–60 字）、`goal`（1–500 字）、`dateFrom`、`dateTo`（YYYY-MM-DD）、`startTime`、`endTime`（HH:mm）、`durationMinutes`（整数）。拒绝额外字段与无效日期。成员 ID 是房间成员关系 ID，不是账号 ID。

## 运行与存储

本机 `local` 模式可创建、查看、授权和关闭单人预览圆桌，数据保存在本机，不生成邀请码或模拟真实伙伴。“清除本机演示数据”会同时清除本机圆桌。多人操作需切换 `api` 模式并使用不同后台会话。

新增迁移 `20260929020000_roundtables`，只新增圆桌状态枚举、圆桌表和成员表，不删除或修改已有个人记录。升级前备份，执行 `npm run db:generate`、`npm run db:deploy`、`npm run check` 后启动后台。

数据库模式的创建、加入、授权和成员变更使用可重试串行化事务，并以唯一约束防止重复成员。测试验证 3 人容量和 20 个进行中房间的并发限制。
