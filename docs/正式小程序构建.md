# 正式小程序构建

更新日期：2026-10-03。已实现独立正式构建与产物检查；尚无实际服务器和域名，当前未生成用于上传的正式版本，也未上传微信体验版。

## 使用流程

后台 HTTPS、合法域名和真实凭证准备好后，在项目根目录执行（将地址替换成实际后台域名）：

```powershell
npm.cmd run build:mini:release -- --api-origin https://实际后台域名
```

命令读取根目录 project.config.json 的 AppID，编译完整小程序，单独生成 `releases/mini-时间-随机编号/`。源码中的 local/demo 配置和 `dist/miniprogram` 保持不变。产物强制使用 api/wechat 和传入的 HTTPS 地址，不需要手动修改开发配置再改回来。

该命令拒绝游客 AppID、HTTP、本机/IP、非默认 HTTPS 端口、示例域名，以及带凭证、路径、查询或片段的地址。仅做格式检查，不验证域名归属、DNS、证书、AppID 权限或微信合法域名。构建过程不读取后台 .env、不请求微信、不调用模型。

命令输出的 directory 是需要导入微信开发者工具的**独立项目根目录**。目录结构：

```text
mini-时间-随机编号/
  project.config.json          实际 AppID，urlCheck=true
  miniprogram/                 编译代码和页面资源，配置固定 api/wechat/HTTPS
  release-manifest.json        构建时间、Git 状态、地址与 SHA-256 文件清单
```

生成时不会复制 `.env`、根目录私有配置、node_modules、旧 dist 或后台源码。页面资源按 json/wxml/wxss 复制；今后若新增图片等资源类型，需要扩展构建脚本的资源清单并测试后发布。

导入前及上传前执行：

```powershell
npm.cmd run check:mini:release -- "releases/mini-命令输出的实际编号"
```

配置错误、文件缺失、修改或新增未列出的文件，会返回非零退出码。开发者工具可能生成 project.private.config.json，该文件不参与哈希清单，但检查会拒绝其关闭 urlCheck；其他本机工具设置不属于上线验收。完整文件校验有助于发现误修改，不能证明代码来源可信或替代签名验证。

如产物文件发生变化，不编辑旧发布目录，重新构建会产生新目录。失败的编译停留在 `.building-*` 目录，不要导入或上传；只有构建并自检全部成功才生成 mini-* 目录。releases 已加入 Git 忽略规则。

manifest 中 sourceRevision 是构建时所在仓库 HEAD；sourceDirty=true 表示还存在未提交文件，null 表示无法读取 Git 信息。此字段不等于源码都已包含在该提交中。最终对外发布前应提交经审核的源码，并重新构建以便定位版本。

## 两类构建的区别

| 命令 | 用途 | 输出 |
|---|---|---|
| npm run build:mini | 本机开发，使用源码中当前配置 | dist/miniprogram |
| npm run build:mini:release -- --api-origin 实际地址 | 独立正式模式构建，强制 api/wechat/HTTPS | 新的 releases/mini-* 目录 |
| npm run check:mini:release -- 发布目录 | 检查产物配置与文件一致性，不上传 | 只读结果 |

正式构建完成后仍须检查开发者工具启用域名和证书校验，上传体验版并进行两个真实微信账号及真机验收。步骤见 [正式部署与真实登录](正式部署与真实登录.md)。现有本机测试使用虚构 AppID/域名，不连接微信，不能标记真实登录已完成。

## 本轮验证

自动测试覆盖无效地址、游客 AppID、类型编译失败、开发配置不变、不复制密钥与旧文件、重复构建不覆盖、文件修改检测、私有域名校验设置，以及完整小程序源码在隔离目录的编译。测试产物生成在隔离临时目录并清理，不保留可能被误上传的虚构正式包。本轮无后台接口或数据库迁移变更。
