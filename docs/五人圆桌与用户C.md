# 五人圆桌与用户C

圆桌上限现在是5人（含发起人），第6人无法加入；后台内存与PostgreSQL两种模式均校验，数据库行锁防止并发超员。不需要数据库迁移。

秘书协商支持2至5人，全员授权后由发起人启动，最多5轮。每轮按成员顺序提出或接受候选，必须本轮每位秘书都选择同一时间才生成方案，不能仅凭首尾两人意见相同就忽略中间成员。共享反馈只有候选与决策，不含私人课程、偏好及理由。最后仍须全部真人接受才写入日程。

人数增加意味着模型调用与耗时增加，单次仍受6分钟总预算和每人每轮5步限制，最多125次模型调用；不是保证一定跑满5轮或一定达成一致。

执行原有 `npm.cmd run demo:two` 现在会生成A/B/C三个独立预览（保留旧命令名以兼容）。用户C目录是 `dist/demo-C`，在微信开发者工具新窗口导入该目录，首次访问后台时自动创建“测试学生C”演示身份。会话存储键与A/B隔离。C加入现有圆桌仍需邀请码，不自动加入或授权。

验收：A创建圆桌，B/C加入，三人各自授权秘书。发起协商后先让两人接受，确认尚未写入；第三人接受后才写入三人的日程。五人上限、六人拒绝与并发加入由自动化测试覆盖。
