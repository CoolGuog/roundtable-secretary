# 个人秘书与模型接入

一句话变日程。这一块的立场只有一句：**只生成待确认的草稿，绝不自动写入。**

## 接口

```
POST /me/secretary/draft   { "text": "明天下午三点到四点和导师开会" }
```

返回草稿，**不会**创建任何安排。写入仍然走 `POST /me/arrangements`，也就是用户在页面上点一次「确认保存」。

```jsonc
{
  "status": "READY",            // READY 可确认 / NEEDS_INPUT 还缺信息 / UNAVAILABLE 模型不可用
  "title": "和导师开会",
  "date": "2026-10-01",
  "startTime": "15:00",
  "endTime": "16:00",
  "confidence": "HIGH",         // HIGH 明确 / MEDIUM 有推断或冲突提醒 / LOW 缺信息
  "missing": [],                // 缺哪些字段，前端据此让用户补
  "reasons": ["「明天」按北京时间换算为 2026-10-01", "时段取 15:00 至 16:00"],
  "usedMemories": [],           // 参考了哪些个人记忆，便于用户判断依据对不对
  "model": "stub",
  "message": "已生成草稿，确认后才会写入你的日程"
}
```

`GET /health` 的 `secretary` 字段会说明当前是哪种模式，`acceptsModelKeys` 恒为 `false`——接口永不接收模型密钥。

## 三种模式

在后台本机 `.env` 里配置，**仓库默认值是 `off`**：

| 模式 | 说明 | 配置 |
|---|---|---|
| `off` | 未接入模型。明确返回「未接入模型，请手动填写安排」，不伪装听懂 | `SECRETARY_MODE=off` |
| `stub` | 本地规则解析，不联网、结果可解释，用于无密钥演示与测试 | `SECRETARY_MODE=stub` |
| `http` | 调用 OpenAI 兼容接口 | `SECRETARY_MODE=http` + `SECRETARY_API_KEY` + `SECRETARY_MODEL` |

`http` 模式还可选 `SECRETARY_BASE_URL`（默认 `https://api.openai.com/v1`）。

**密钥只从本机 `.env` 读取**，不入库、不进仓库、不写日志，接口也不接受前端传来的密钥。

## 解析规则（stub 模式）

时间与后台一样统一按**北京时间（UTC+8）**解释，与 `apps/api/src/time.ts` 同源。

- 日期：今天 / 明天 / 后天 / 大后天、周三 / 下周三 / 本周五、10 月 3 日 / 10-03
  - 「周三」若本周已过则顺延到下周，并在理由里说明
  - 月日早于今天则按次年理解，并说明
- 时刻：三点 / 三点半 / 15:00 / 十五点，配合上午·下午·晚上判定 12 小时制
  - 「三点到四点」取区间；「两点开始持续一个半小时」按时长推
  - 只说了开始时间 → 默认 1 小时，**并明确说明这是推断**
  - 只说了「下午」 → 按 13:00 起 2 小时内理解，同样说明
- 标题：去掉已识别的日期与时间词后的剩余文本

解析不出来就如实说解析不出来：`status` 为 `NEEDS_INPUT`，`missing` 列出缺什么，四个字段可以是 `null`，**不会给编造的时间**。

## 个人记忆怎么用

个人记忆里 `PREFERENCE` 与 `CONSTRAINT` 会参与判断：如果草稿时段与你记过的限制可能冲突，`reasons` 里会提示，并把用到的记忆列进 `usedMemories`。

**只提醒，不改你的决定**——你说晚上八点半跑步，草稿就还是 20:30，不会因为记过「晚上不运动」就擅自改时间。

发给模型的内容只有：你自己的记忆（最多 20 条，每条截断）、一句话、今天的日期。不含任何他人的数据。

## 模型不可信，所以要校验

`http` 模式返回的内容一律当作不可信输入处理：

- 只接受符合格式的字段，日期不是 `YYYY-MM-DD` 或早于今天就作废
- 开始时间不早于结束时间，否则丢掉结束时间让你重填
- 名称超过 60 字作废
- 模型超时（8 秒）、报错、返回非 JSON → `UNAVAILABLE`，提示手动填写，**不静默返回垃圾结果**
- 答对的字段不会连带作废，省得你重填
