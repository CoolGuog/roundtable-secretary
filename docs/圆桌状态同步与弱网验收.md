# 圆桌状态同步与弱网验收

更新日期：2026 年 10 月 2 日。基于用户主项目提交 `0880afe` 持续开发。

## 使用体验

在后台模式打开圆桌详情后，页面每 5 秒读取一次房间和当前方案。伙伴加入、授权、接受、拒绝、撤回以及全员确认结果会自动更新，不必反复返回列表再进入。页面显示上次更新的北京时间，也支持下拉刷新与「刷新圆桌」按钮。

本机演示不发起轮询；切出或销毁页面后停止，关闭的房间读取完成后停止。返回页面会重新读取。弹窗、写入和候选计算期间暂停定时读取，避免操作结果被旧请求覆盖。

## 失败与恢复

- 临时断网：保留上次内容并明确标记状态未更新，清空旧候选，刷新成功前禁止写操作。自动重试间隔依次为 10、20、30 秒，之后保持 30 秒；恢复后回到 5 秒。
- 首次加载失败：显示错误和刷新入口，不在没有房间信息时持续请求。
- 无权限或已被移除：接口返回 401、403、404 时清除成员、邀请码、方案和候选，停止自动读取。
- 写操作超时：后台可能已经执行，因此只重新查询结果，不自动重发写入。页面提示查看当前状态后再操作。
- 成员、授权或方案变化：清除此前计算的候选，防止继续显示基于旧状态的时段。提交方案时后台仍重新检查可用性。
- 慢请求：较早的读取结果不能覆盖新刷新或写入后的状态；离开页面后迟到的响应不再更新页面。
- 切出期间未确认的弹窗：返回后旧确认回调不执行操作，需要用户重新操作。

`tests/mini-auth.test.mjs` 补充状态码与网络超时断言，确认写入不会自动重放，临时断网不会丢失有效令牌。

`tests/mini-roundtable-flow.test.mjs` 启动真实本机 HTTP 后台，让两份独立的小程序页面逻辑与请求服务各用自己的演示会话，验证：

1. 创建、加入后另一页面自动出现伙伴。
2. 双方授权，提出方案，再撤回；伙伴页面自动看到撤回。
3. 重新发起，一方接受时双方均无新增日程。
4. 另一方接受后，双方自动显示已确认，各自恰好有一条活动日程。
5. 移除成员后，该成员页面清除房间与方案。

该流程使用内存后台、受控计时器和模拟弹窗回调，不依赖开发数据库，不代表真实微信登录或真机验收。运行后关闭后台，不留测试会话或日程。
