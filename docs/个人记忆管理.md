# 偏好与个人记忆管理

更新日期：2026 年 9 月 29 日。

## 使用方式

重新构建小程序后，打开“我的 → 管理我的记忆”。点击“新增记忆”，选择偏好、限制或备忘，填写标题和内容后保存。每条记录可编辑、删除，并显示来源和北京时间的更新时间。删除前需要确认；取消会保留记录。

标题最多 40 字，内容最多 500 字；两者都不能为空。每个用户最多 100 条。记忆当前只由本人查看和管理，尚未接入模型、自动安排或圆桌共享。

默认本机模式会在当前模拟器或设备保存演示记忆。后台模式复用日程的登录会话，记忆按账号隔离；PostgreSQL 模式下后台重启不会清除数据。演示身份过期后不能自动找回旧身份的数据；微信登录模式设计为重新登录同一账号后恢复，但真实微信换码尚待验收。

“清除本机演示数据”会清除本机演示安排、记忆和演示会话，不删除后台数据，不撤销微信登录。仅使用虚构测试数据。

## 接口约定

所有接口需要会话 Bearer Token，所属用户由后台确定。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/me/memories` | 按更新时间倒序返回本人记录 |
| POST | `/me/memories` | 新增本人记录 |
| PUT | `/me/memories/:id` | 完整替换类型、标题和内容，保留 ID 与创建时间 |
| DELETE | `/me/memories/:id` | 删除本人记录，成功返回 204 |

新增和更新只接受 `category`、`label`、`content` 三个字段，均必填；类型为 `PREFERENCE`、`CONSTRAINT` 或 `NOTE`。与日程的部分字段编辑不同，记忆更新必须传全这三个字段。空白会去除首尾空格；额外字段、无效类型、空值或超长值返回 400。越权与不存在统一返回 404，未登录返回 401。

返回 ID、类型、标题、内容、来源、创建及更新时间，不返回所属用户 ID 或内部来源引用。手动新增与编辑的来源由后台设为 `USER_INPUT`；将来的秘书提炼记录被用户编辑后也转为用户录入，清除旧内部引用。当前没有自动提炼写入入口。

本轮复用既有 `personal_memories` 表，无新数据库迁移；并发新增使用可重试的串行化事务保护单用户数量上限。
