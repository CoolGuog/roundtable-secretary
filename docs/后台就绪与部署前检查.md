# 后台就绪与部署前检查

更新日期：2026-10-02。

## 存活与就绪

`GET /health` 保持原有响应，表示 HTTP 进程能够处理请求，展示当前存储和身份模式。它不保证数据库可用。

新增 `GET /ready`，无需登录且禁止缓存：

- 内存模式返回 `200 { "status": "ready", "persistence": "memory" }`，不代表持久化环境就绪。
- PostgreSQL 模式实际查询全部 10 张当前业务表使用的列，成功返回 `200 { "status": "ready", "persistence": "postgres" }`。
- 查询失败或超过 2 秒未完成，返回 503 和通用提示“后台存储暂未就绪”，不返回数据库地址、凭证或原始 SQL 错误。
- 同一进程的并发探测共用一次数据库查询，完成结果缓存 1 秒。超时只结束 HTTP 等待，不会强行取消数据库请求；底层查询未结束前不会重复发起探测。

数据库查询均为 `LIMIT 0`，不读取记录内容、不创建用户、不调用微信或模型。探测只验证当前表和列可查询，不验证索引、外键、全部字段类型、写权限或外部模型连接；部署迁移及结构差异检查仍需单独执行。

后台启动时同样执行表与列检查。原先仅检查会话表，漏跑后续迁移也可能启动；现在缺少日程、圆桌、方案、记忆或保存重试表时会拒绝启动，并提示核对配置和迁移。

## 只读命令

先启动后台，再在项目根目录运行：

```powershell
npm.cmd run check:api
npm.cmd run check:api -- http://127.0.0.1:3000 --require-postgres
npm.cmd run check:api -- https://你的后台域名 --require-postgres --require-wechat
```

默认地址为 `http://127.0.0.1:3000`。检查两个只读接口、响应格式、存储模式是否一致；严格选项能发现误启内存存储或演示身份。每个请求最多等待 3 秒，禁止跟随重定向；地址不能带凭证、额外路径、查询参数或片段，非本机地址必须使用 HTTPS。

通过退出码为 0，失败为 1。命令只输出固定状态字段，不回显上游错误内容或输入地址中的凭证。即使通过，`liveLoginVerified` 仍为 false，真实换码必须另验。

## 部署前顺序

1. 在目标环境准备 Node.js、PostgreSQL 与独立后台配置，密钥只写入不提交 Git 的环境配置。
2. 保存数据库备份，核对代码版本，执行 `npm run db:deploy`；不要使用重置数据库作为升级步骤。
3. 构建后台并启动，运行 `check:api --require-postgres`，确认 200 就绪及模式正确。
4. 配置 HTTPS 入口、证书及微信合法请求域名，设置小程序后台地址，保持证书与域名校验开启。
5. 先在隔离测试环境验收微信换码，再验证两个真实账号的数据隔离、共同确认、退出重登与手机网络恢复。

以上是检查顺序，不是已完成部署的记录。后续已补齐生产启动配置校验、登录限流与 HTTPS 代理模板，步骤见 [正式部署与真实登录](正式部署与真实登录.md)。后台仍仅监听本机，由 Nginx 提供公网 HTTPS；服务器、域名、AppSecret、证书与监控实际配置仍待完成。部署后使用 `--require-production` 同时要求 HTTPS、生产标记、PostgreSQL 和微信模式。当前无需修改主项目的 local/demo 模式。

## 测试范围

自动化覆盖并发探测去重、成功/失败缓存、超时后不堆积、故障恢复、503 脱敏、内存模式与真实环境区分，以及只读检查对非法地址、错误模式和异常响应的拒绝。

PostgreSQL 集成测试在随机隔离 schema 中临时改名保存重试表，验证 `/health` 仍存活、`/ready` 返回 503、新实例拒绝启动；恢复表后就绪恢复。结束后清理隔离 schema，不改动开发库 public 数据。

同时修复了协商测试写死 2026 年 10 月 1 日导致自然过期的问题：有效圆桌和忙时安排改用同一组相对未来日期；非法日期、时段及过期保护的断言仍保留。

最终结果：常规检查 105 项通过、1 项数据库套件默认跳过，类型检查和构建通过；PostgreSQL 单独检查 45 项通过。真实 HTTP 与 PostgreSQL 下，命令行要求持久化时退出 0，要求微信身份时正确拒绝演示身份并退出 1。测试后台和随机隔离 schema 均已清理。本轮没有新迁移，不改动开发数据库 public 数据。
