# 双窗口演示

两个模拟器项目连接同一台本机后台，各自使用独立的演示身份。无需在 Console 手工交换令牌。

## 打开项目

| 窗口 | 导入目录 | 标识 |
|---|---|---|
| A | `D:\万象无限\roundtable-secretary\dist\demo-A` | 标题“圆桌秘书 · 学生A”，页面显示“测试学生 A” |
| B | `D:\万象无限\roundtable-secretary\dist\demo-B` | 标题“圆桌秘书 · 学生B”，页面显示“测试学生 B” |

在微信开发者工具项目列表分别导入两项并打开两个窗口，然后分别编译。后台必须运行在 `127.0.0.1:3000`。首次请求会自动创建各自身份，原项目及先前手工创建的身份数据不自动导入；先在 A 创建新圆桌，再在 B 用其邀请码加入。

如果本地 HTTP 被拦截，确认各窗口本地设置勾选“不校验合法域名……”。生成项目的私有配置已关闭本机域名校验，公共配置仍开启。仅用于开发者工具模拟器，不用于上传发布或真机。

## 源码与重新构建

两项都是同一份源码的构建结果，不要直接修改生成文件。改动原项目源码后执行：

```powershell
npm.cmd run demo:two
```

再在两个窗口编译。无需复制 node_modules、数据库、.env 或密钥。两项项目输出都位于 Git 忽略的 dist 目录。

## 身份隔离

同一 AppID 的窗口即使共享本机存储，演示会话缓存也按 A/B 分开，两个窗口会创建不同后台用户。刷新不会自动换用户，直到演示会话过期或清除会话。

命名身份只在本机 API 演示模式生效，真实微信登录不受影响。演示会话有效期仍为一小时，过期后按页面提示重试会创建新身份，旧数据仍留在旧身份中。

验证：8 项前端会话测试通过，包括共享存储下的 A/B 隔离与刷新保留会话，小程序构建通过。双窗口实际 UI 行为仍需手动打开验收。

## 圆桌改期验收（2026-10-10 修复）

同一圆桌代表同一活动。首次全员接受后生成各自日程；再次协商并全员接受后更新原记录，不追加另一条。原时间在新方案全员确认前保持有效。撤回、拒绝、失效或最终写入失败均保留原记录；改期允许与本活动旧时间重叠，其他安排仍参与冲突检查。不同圆桌即使同名也互不替换。

1. 两个窗口重新编译，创建新的测试圆桌，加入并授权忙闲。
2. 首次全员接受方案，双方日程各出现一条活动。
3. 在同一圆桌重新计算时间，选择另一候选时段，仅一方接受，检查双方仍为原时间。
4. 另一方接受后，进入双方日程页：原条目显示新时间，各只有一条。
5. 再次提案后撤回或拒绝，检查已确认日程未变化。

旧版本日程没有保存来源圆桌。迁移保留这些记录，不能仅凭标题可靠区分手动安排和圆桌安排。因此，旧测试圆桌的遗留条目需要用户按实际时间手动删除一次；建议新建圆桌验收。迁移不会自动绑定或清理旧条目。

技术验证：`npm.cmd run check` 65 项通过、1 项数据库测试跳过；单独执行 `npm.cmd run test:postgres` 40 项通过。覆盖部分重叠改期、全员确认前不更新、冲突失败整体回滚、满额更新、同名个人安排保留、撤回与拒绝保留。真实双窗口 UI 验收待用户完成。

## 手动选时与手动改期（2026-10-10）

圆桌详情新增“手动选时或改期”：选择日期、开始和结束时间，点击“提出这个时间”，在弹窗确认后生成待确认方案。选择开始时间会按约定活动时长自动带出结束时间。手动时间可以不在推荐列表内，也不限于半小时起点，但必须在圆桌日期、每天时间窗口内，符合约定时长且尚未开始。

手动提案不要求成员授权忙闲。提案时只检查已授权成员忙闲，全员接受时检查所有成员冲突，不披露私人日程标题。至少两名成员才能提案；已有待确认方案时，先完成确认或由提案人撤回。手动改期不会继承旧方案投票，每个成员必须重新接受；确认前保留原日程，全部确认后更新。

双窗口验收：首次确认后在同一圆桌手动提出另一时间；先由一方接受，检查双方日程仍为原时间；另一方接受后，检查各只有一条新时间日程。再验证弹窗取消不提案、拒绝或撤回不改旧日程、冲突时间被拦截。

验证：类型检查和构建通过；普通测试 67 项通过、1 项数据库测试跳过，另新增 2 项页面交互测试通过；真实 PostgreSQL 测试 42 项通过。双窗口 UI 新功能仍需手动验收。

## 当天空档、默认时间及浮层提示修正

- 共同空档只计算尚未开始的时间。下午检查时，上午空闲也不再作为候选；无解文案明确说明“未来共同空档”，时间窗口快结束时提示选择更晚的日期范围。
- 手动选时不再固定填圆桌起点（例如今天 09:00），默认选择未来时间；当天放不下约定时长时，若范围允许则默认下一天。范围内没有剩余未来时间时展示空值和明确说明。手动选择过去时间仍会被拒绝。
- 圆桌操作错误改为屏幕上方固定的半透明浮层，2 秒自动消失，不随页面滚动；连续提示重置计时器，离开页面清理计时器。

回归验证：`npm.cmd run check` 72 项通过、1 项数据库测试跳过；真实 PostgreSQL 测试 42 项通过。新增固定北京时间测试验证上午过去、下午空档、当日剩余被占用、默认未来时间、日期切换、窄时间窗口和浮层生命周期。实际浮层样式与双窗口操作待手动验收。

## 接受方案后的反馈修正

以服务端返回的本人投票判断按钮状态，提案人和其他成员处理一致。接受成功后按钮显示“已接受”并禁用重复点击，同时显示等待其他成员的说明和 2 秒浮层；最后一位接受时提示全员已接受、日程已更新。投票失败不提前显示成功，刷新后仍按服务端状态显示；新提案需要重新接受。

验证：6 项圆桌页面测试通过，小程序类型检查及双窗口构建通过。手动验收：由发起者先接受改期方案，确认按钮与本人投票均显示已接受，等待提示可见；另一成员接受后刷新圆桌，显示全员确认。
